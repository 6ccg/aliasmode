# Local desktop customizations

- **Links (Windows/macOS):** install the desktop app, then open Settings → Browser routing to select it as the default browser. Windows opens Default apps; macOS asks for confirmation. Choose a local Profile or an installed browser for each link. Drag the handles to arrange browsers and Profiles; the order and manually added browsers are saved on this computer. Icons come from the installed applications, with a letter/number fallback when unavailable.
- **Windows:** the installer registers HTTP/HTTPS handling for the current user and removes its registration on uninstall. It does not change the user's default automatically. Added browsers must be `.exe` files; macOS uses `.app` bundles.
- **Window behavior:** a link opens only the separate compact chooser. It presents the link before loading Profiles or icons, without waiting for browser process scans. A normal launch opens the dashboard. Close/Escape dismisses the current link; running Profiles stay open. Links remain in memory until opened, dismissed, or the manager exits. Failed opens can be retried.
- **Random fingerprint:** an optional Local Profile setting, off by default. A fresh launch regenerates supported device settings and replaces manual device overrides. Reusing a running Profile does not regenerate it. Cookies, login data, OS, proxy, and language stay unchanged; this is not a new anonymous identity.
- **Profile identification:** window titles include the name and number. Windows Firefox uses native per-Profile taskbar groups; Chromium already groups its separate data directories. macOS Chromium requests the existing number as a running Dock badge when the engine supports it. No permanent launcher apps are created.
- **macOS Firefox Dock number:** uses the bundled browser's Marionette protocol and native Dock service, without modifying its engine or app bundle. The connection closes after setting the number; Firefox's loopback listener ends when that browser exits. A changed number takes effect on its next launch. No badge is requested for headless browsers. Native macOS display has not been verified on this Windows machine.

The fork retains upstream networking, downloads, and updates. Installing an upstream update can replace these customizations. Versions use the upstream version plus `.modN`; the optional ARM64 workflow produces preview artifacts.

Development uses `main` for the upstream base and `codex/customizations` for these changes. Core checks: `bun run typecheck`, `bun test ./url-routing.test.ts ./web/url-router.test.tsx ./random-fingerprint.test.ts`, and `cargo test --manifest-path src-tauri/Cargo.toml --lib` after preparing desktop resources. Native macOS window/Dock behavior still needs a Mac to verify.
